STEP 1 — Build M6: content, newsletter, polish, hardening, deployment prep

Scope:
1. Education & research (spec section 7):
   - Articles with types EDUCATION, GUIDE, RESEARCH, plus a structured Gemstone Reference Library: one page per gemstone type with properties, hardness, common origins, common treatments, how to judge quality, care, and what affects price.
   - Each library page links to matching catalogue listings and valuation.
   - Content search, tags, related content, reading time, and SEO metadata.
2. Market news: news posts with date, source attribution, and categories. A /news listing and detail pages.
3. Admin content publishing:
   - Markdown editor with live preview. Render with strict sanitisation (no raw HTML, no scripts).
   - Cover images via StorageProvider.
   - Statuses DRAFT / SCHEDULED / PUBLISHED / ARCHIVED, with scheduled publishing.
   - Authors are admin users. Audit log on publish/unpublish.
   - The homepage teaser sections now link to the real pages, and the "coming soon" pages are gone.
4. Demo content: about 8 original articles/guides, reference library pages for the 7 categories, and 5 news posts. Write original text; never copy from websites. Label all of it "Demo – needs expert review" and respect ALLOW_DEMO_SEED.
5. Newsletter (spec section 8):
   - Subscribe forms in the footer, on the homepage and on article pages.
   - Double opt-in by email. Store a consent record (time, IP hash, source) for India DPDP compliance.
   - Topics: Education, Market news, New listings, Platform updates.
   - A token-based preferences page that works without login. One-click unsubscribe with a List-Unsubscribe header.
   - Logged-in users manage subscriptions in account settings.
   - Admin campaigns: compose in markdown, choose topics, preview, test send, schedule, then send in batches through EmailProvider via a job, with send stats.
   - An automated weekly digest of new articles/news to topic subscribers.
   - A Resend webhook endpoint (signature-verified) that suppresses bounced and complained addresses.
6. Legal and basics:
   - Pages for Terms, Privacy Policy, Cookie Policy and Seller Agreement, with placeholder text clearly marked "Draft – needs legal review".
   - A cookie notice for the analytics cookie.
   - Custom 404 and 500 pages.
   - Fix every footer/nav link that still 404s.
7. Accessibility and polish:
   - Add @axe-core/playwright checks to the journeys, then fix violations: contrast, labels, alt text, focus states, keyboard navigation in carousels and dialogs.
   - Consistent loading, empty and error states on every page.
   - A design-consistency pass across all pages, keeping the existing premium design.
8. Hardening (everything on the M6 list in ROADMAP.md), including:
   - Admin service functions check roles themselves.
   - Listing limit and featured-slot checks are atomic (transaction + lock), and pending-review listings are counted.
   - Security headers: CSP, HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy.
   - TRUSTED_PROXY_COUNT config for client IP instead of the fixed one-proxy assumption.
   - A production env check that refuses console email/SMS providers and demo seeds.
   - A cleanup job for old rate-limit rows.
   - npm audit fixes.
   - Optional error monitoring hook (Sentry via env, off by default).
9. Deployment prep, hosting-agnostic:
   - Multi-stage Dockerfile using Next standalone output.
   - docker-compose.prod.yml with app, Postgres and a worker container that runs scheduled jobs: notify:flush every 5 min, analytics:rollup daily at 00:30 IST, newsletter sends, scheduled publishing, and cleanup.
   - An S3-compatible StorageProvider (works with AWS S3, Cloudflare R2, DigitalOcean Spaces), selected by env.
   - Migrations run on deploy. /api/health endpoint.
   - docs/DEPLOYMENT.md covering a VPS with Docker + Nginx + SSL certificate, and notes for Vercel + managed Postgres. Include backups, env reference, and a go-live checklist: MSG91 DLT registration, Resend domain verification, a strong admin password, no demo data, legal review, real reference prices, client-confirmed membership rules, and the open "SSL-related options" question.
10. Phase 1 completion report: docs/PHASE1-REPORT.md mapping every item in the original Phase 1 spec and docs/client-brief.md to where it's implemented and how it's tested, plus known limitations and a client handover checklist.
