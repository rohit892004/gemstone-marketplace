STEP 1 — Build M4: Gemstone valuation (spec section 6 + client brief)

Scope:
1. Two ways to request a valuation:
   - "Request valuation" on any product page, prefilled with that listing's details and images, for that specific gemstone.
   - A standalone /valuation page where a buyer or seller uploads their own gemstone.
   Any logged-in buyer or approved seller can request one.

2. Step 1 – Upload: a 3-step wizard. Images (required, at least 1) and optional video via StorageProvider with the existing validation and EXIF stripping. Details: gemstone type, category, shape/cut, carat, dimensions, colour, clarity, origin, treatment, certificate (lab from lab table + number + optional file), and notes. Save draft, then submit.

3. Step 2 – Analysis: a rule-based indicative valuation engine written as pure functions with thorough unit tests.
   - Reference price-per-carat table by gemstone type × quality grade × carat band, editable by admin.
   - Multipliers for origin, treatment and certificate lab.
   - Output: estimated value, low–high range, confidence (LOW / MEDIUM / HIGH) based on data completeness and certification, and a plain-language list of the factors used.
   - Route to expert review automatically when confidence is LOW, the estimate is above an admin-set threshold, or the gemstone type has no reference data. The requester can also ask for expert review.
   - Do NOT claim the system analyses the images; the images are for the expert.

4. Expert review:
   - Add a VALUATOR role that only admin can create (no public signup).
   - Admin assigns requests to valuators.
   - Valuators see their queue, can view the media and details, request more info from the requester (status NEEDS_INFO, requester notified), and adjust value, range and confidence with notes, then sign off.
   - Statuses: DRAFT, SUBMITTED, AUTO_VALUED, IN_EXPERT_REVIEW, NEEDS_INFO, COMPLETED, REJECTED (with reason).
   - Everything is audit logged.

5. Step 3 – Results: page showing estimated value, range, confidence, factors, who valued it (auto vs expert), and a clear disclaimer: indicative only, not a certified appraisal.

6. Downloadable PDF report with a reference number and a QR code linking to a public verification page /valuation/verify/[ref]. That page only shows the reference, date, gemstone type, status (valid/withdrawn) and auto/expert. It never shows the price or the requester.

7. Privacy:
   - A valuation is private to the requester, assigned valuators and admin.
   - If a buyer values a seller's listing, the seller is NOT told the result.
   - A seller who values their OWN listing may choose to publish the completed report on that listing, shown as "Platform indicative valuation" with its date. This works alongside the M2 seller-uploaded valuation documents.

8. Dashboards:
   - Buyer (and the seller buying side) Valuations and Saved reports tabs now work: list, status, results, PDF download.
   - Notifications (in-app + email) on every status change.

9. Admin:
   - Valuation queue with filters.
   - Assign/reassign valuators and create/deactivate valuator accounts.
   - Reference price table editor (with import/export CSV).
   - Expert-review threshold setting.
   - Withdraw a report (the verification page then shows "withdrawn").
   - Basic stats.

10. Rate limits on valuation submissions. Run the contact-detail moderation on notes.

11. Demo seed: reference prices for the 7 categories labelled "Demo — indicative", one demo valuator account, and a few demo valuations in different statuses. Respect ALLOW_DEMO_SEED.
